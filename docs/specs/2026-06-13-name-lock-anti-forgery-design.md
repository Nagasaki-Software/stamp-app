# StampApp 名前ロック（偽造防止）設計書

- 作成日：2026-06-13
- 種別：仕様書（design doc）
- 対象範囲：印鑑の「名前」のロックと管理者による変更のみ。検出・押印・色・マーカー等の既存機能は変更しない

---

## 1. 目的

印鑑の名前を他人がなりすまし偽造できないよう、**一度確定した名前はグレーアウトして変更不可**にする。
ただし**一部の管理者はキーワードで特定ファイルを修正することで名前を変更可能**にする。
また**`settings.json` を消しても名前を偽造できない**ようにする。

## 2. 脅威モデルと正直な限界

- 本アプリは利用者自身のPC上で動く単体EXEであり、**高度な攻撃（EXE解析・秘密鍵抽出等）を100%防ぐことは原理的に不可能**。
- 採用方針＝**「手軽重視：自己設定→ロック」**。狙いは「**普通の利用者が名前を打ち替えて他人になりすますのを実質不可能にする**」こと。
- 達成すること：
  - 一度確定した名前はUIで変更不可（グレーアウト）。
  - 手書きでロックファイルを書き換えても**署名照合で検知**し押印停止。
  - **`settings.json`（Documents配下）を消してもロックは残る**（ロックは別ファイルに保存）。
  - 他人のロックファイルをコピーしても、Windowsアカウント不一致で無効。
- 残る限界（許容）：
  - ファイル2か所**とレジストリ値**をすべて削除すると初回状態に戻り、**自分のWindowsアカウントで**名前を再設定できる（高度な操作で、普通の利用者には困難）。
  - 結論：**他人のWindowsアカウントでログインしない限り、他人名義の押印は実質できない**。

## 3. ロック情報（identity.lock）

- 保存先（ファイル2か所＋レジストリ1か所の冗長保存）：
  - 主：`%LOCALAPPDATA%\StampApp\identity.lock`
  - 副：`%APPDATA%\StampApp\identity.lock`
  - レジストリ：`HKEY_CURRENT_USER\Software\StampApp`（値名 `identity`、管理者権限不要）
  - ファイルはいずれも隠し属性。`settings.json`（`Documents\StampApp`）とは別。
- 形式（JSON）：
  ```json
  {"name": "山田 太郎", "win_user": "user01", "created": "2026-06-13 10:00:00", "sig": "<hex>"}
  ```
- 署名：`sig = HMAC_SHA256(SIGNING_SECRET, name + "|" + win_user)`（`SIGNING_SECRET` はアプリ内蔵）。
- `win_user = getpass.getuser()`。読み込み時に現在の `win_user` と一致しないレコードは「自分のロックではない」とみなす（他人のファイルコピー対策）。

## 4. 検証と異常時の挙動

ロック読込時：
- 主・副いずれかに「現在の `win_user` 用の有効レコード（署名一致）」があれば **ロック状態**。名前はそのレコード値。
- レコードはあるが**署名不一致（改ざん）** → **異常**：エラーダイアログ「本人名情報が破損/改ざんされています。管理者に連絡してください」を表示し、**押印を不可**にする（偽名押印を許さない）。
- 主・副どちらも無し → **未ロック**（初回状態）。名前欄は入力可能。

## 5. ロックのタイミングとUX

- 未ロック時：名前欄は入力可能。
- **初回「押印実行」時**に確認ダイアログ：「この名前『○○』で確定します。以後の変更には管理者キーワードが必要です。よろしいですか？」
  - OK → identity.lock を主・副に署名付きで書き込み、その後通常の押印処理へ進む。以後グレーアウト。
  - キャンセル → ロックせず押印も中止（名前を直せる）。
- ロック時：名前欄は `state="disabled"`（グレーアウト）。所属・サイズ・線・色・書体は従来どおり編集可。
- 既存利用者の移行：既存 `settings.json` の名前は（未ロックの）名前欄に初期表示され、次回の初回押印で確定する。

## 6. 管理者による変更（ファイル方式）

- 管理者が `%LOCALAPPDATA%\StampApp\admin_override.txt` を作成し記入：
  ```
  keyword=<管理者キーワード>
  name=<新しい名前>
  ```
- **アプリ起動時**に当ファイルがあれば処理：
  - `SHA256(keyword) == ADMIN_KEY_HASH`（内蔵）なら、名前を新値で更新し identity.lock を**再署名**して主・副へ書き込み、**override.txt を削除**。「管理者により名前を変更しました：○○」を表示。
  - 不一致なら変更せずエラー表示「管理者キーワードが正しくありません」（ファイルは残し、管理者が直せるようにする）。

## 7. アプリ内蔵の定数（`core/identity.py`）

- `SIGNING_SECRET`：ランダム32バイト（hex）。HMAC鍵。平文埋め込み（手軽モデルの許容範囲）。
- `ADMIN_KEY_HASH`：管理者キーワードの `SHA256`。**キーワード平文は埋め込まない**。
- 管理者キーワード平文は**管理者にのみ共有**（アプリ・リポジトリには保存しない）。後から任意値で再ビルドして変更可能。

## 8. 既存機能との関係

- 名前の「権威」は identity.lock。ロック時は表示・押印・設定保存いずれも identity.lock の名前を使う。
- `settings.json` は引き続き他の設定（所属・サイズ・色・選択マーカー等）を保存。名前はロック時 identity.lock 優先。
- ログ（`logger.py`）・PDFメタデータ・ハッシュチェーン・検出・押印は**変更なし**。

## 10. テスト方針

- 署名生成・検証が一致／不一致（改ざん）を正しく判定。
- `win_user` 不一致レコードは未ロック扱い。
- override：正しいキーワードで名前更新＋override.txt削除、誤キーワードで不変。
- 冗長保存：主を消しても副でロック維持。両方無しで未ロック。
- 既存テスト（markers/detector/settings/stamp_color 等）が回帰しない。

## 11. スコープ外

- 管理者発行（公開鍵）方式、押印ログへの Windows アカウント記録（追跡強化）は今回実装しない。
