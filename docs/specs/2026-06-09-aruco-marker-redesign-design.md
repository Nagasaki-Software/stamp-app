# StampApp マーク検出 全面再設計（ArUcoマーカー方式）設計書

- 作成日：2026-06-09
- 種別：仕様書（design doc）／既存「2026-05-22-stamp-app-design.md」のマーク検出部分を全面置換
- 対象範囲：**マークの検出方式とマーカーの配布のみ**。印鑑PNG生成・押印・ログ・設定永続化・PDFメタデータ・EXE配布形態は変更しない

---

## 1. 背景と目的

### 1.1 現状の問題
スキャンPDFのマーク認識率が低く、かつ余白などへの誤検出が多発している。原因は検出方式そのものにある。

現行は「丸囲み文字（㊎㊗㊦㊨㊀）」をOpenCVのテンプレートマッチング（正規化相互相関）で探している。これは **「どれくらい似ているか」のあいまい一致** であり、原理的に次の限界を持つ：

- スキャン画像では「丸＋漢字」が他の漢字・印影・表のマス目の丸と似てしまう
- しきい値を厳しくすると見逃し、緩めると誤検出が増えるジレンマから抜け出せない
- スケール総当たり・回転総当たり・サンプルマーク指定などの対症療法を重ねても、**誤検出ゼロを保証できない**

### 1.2 目的
**「機械が読むために設計された専用マーカー（ArUco）」を目印に使い、誤検出を原理的にゼロへ近づける。** ArUcoは模様の中に誤り検出符号を内蔵し、回転・サイズ変化・スキャン汚れがあっても正しく検出し、無関係な模様を拾わない。OpenCVに標準搭載（追加インストール不要、確認済み：opencv 4.13、`cv2.aruco` 利用可）。

## 2. 方針の核心

| 項目 | 変更前 | 変更後 |
|------|--------|--------|
| 目印 | 丸囲み文字 ㊎㊗㊦㊨㊀ | ArUcoマーカー（ID 0〜4の5種、`DICT_4X4_50`） |
| 検出 | テキスト検索＋テンプレート照合の自動切替 | **ページ画像化→ArUco検出の単一方式** |
| 誤検出対策 | スケール/回転総当たり・NMS・インク比率・サンプル指定 | **すべて不要**（ArUcoが内部で吸収・棄却） |
| 目印の入手 | キーボードで文字入力 | アプリが書き出すマーカー画像を貼付／印刷 |
| 対応経路 | Acrobat・スキャン | Acrobat・**Word・Excel**・印刷→スキャン |

**変更しないもの**：印鑑PNG生成（`stamp_generator.py`）、押印・白塗り消去・上書き保存（`pdf_stamper.py`）、改ざん防止ログ（`logger.py`：ハッシュチェーン＋PC名）、設定永続化（`settings.py`）、PDF埋め込みメタデータ、配布形態（単一EXE／onedir）。

## 3. マーカー仕様

- 辞書：`cv2.aruco.DICT_4X4_50`（4×4の大きなマス＝小サイズ印刷・低画質スキャンに強い。5種で十分な容量）
- 種別：**ArUco ID 0〜4 の5種**。アプリ上の表示名は **No.1〜No.5**（用途は従来同様「承認者ごとの目印」）
- 構成（1マーカー画像）：
  1. ArUcoパターン本体（黒の6×6モジュール：データ4×4＋黒枠1モジュール）
  2. **クワイエットゾーン**（パターン外周の白い余白。最低1モジュール幅、推奨2モジュール幅。検出に必須）
  3. **見分け用ラベル**（パターン下に「No.1」等の文字を併記。検出には使わず人の識別用）
- 推奨実寸：**約10mm四方**（白余白込み）。6〜20mm程度で確実に検出。

## 4. マーカーの書き出し（新機能）

アプリに「**マーカー書き出し**」ボタンを追加。保存先フォルダを選ぶと、次を一括出力する。

| 出力 | 個数 | 形式 | 主な用途 |
|------|------|------|----------|
| マーカー画像 | 5 | 高解像度PNG | Acrobat / Word / Excel に「挿入→画像」で貼付、印刷 |
| マーカー画像 | 5 | ベクターSVG | Office 2016以降で最高精細（拡大・圧縮に強い） |
| 印刷用シート | 1 | A4 PDF | 印刷→スキャン用の見本（5種＋サイズ目安＋使い方） |

同一内容を `assets/markers/` にも同梱し、EXEに同梱する。`使い方.txt` に置き場所と手順を記載。

### 4.1 PNG（Office画像圧縮対策）
Officeは保存時に画像を自動圧縮することがあるため、**十分高解像度のPNG**で書き出す（目安：パターン本体1200px角以上。約10mmに縮小して貼っても、Officeの圧縮後も各モジュールが潰れない画素数）。ArUco 4×4はもともと圧縮に強く、これで実害は出ない。

### 4.2 SVG（ベクター）
ArUcoの6×6モジュール行列を、黒モジュール＝`<rect>`としてSVGに変換。クワイエットゾーンとラベル文字も含める。`width="10mm"`等の実寸指定とし、拡大・縮小・印刷で劣化しない。

### 4.3 アプリ／文書への貼付け手順（`使い方.txt`へ記載）
- **Acrobat**：編集 → 画像を追加 → マーカーPNGを選択 → 約10mmで配置
- **Word / Excel**：挿入 → 画像 → このデバイス → マーカー（PNGまたはSVG）→ サイズを約10mm四方に設定（**縦横比固定／斜めにしない**）
- 画像圧縮を確実に避けたい場合：ファイル → オプション → 詳細設定 → 「ファイル内のイメージを圧縮しない」にチェック
- いずれも、最終的にPDF化（保存／印刷→スキャン）した時点でアプリが検出できる

## 5. 検出フロー（新）

```
各ページ:
  1) ページを 250DPI でグレースケール画像化（get_pixmap）
  2) detector.detectMarkers(gray) で 全マーカーの四隅とID を取得
       detector = cv2.aruco.ArucoDetector(
                    getPredefinedDictionary(DICT_4X4_50),
                    DetectorParameters())   # 角のサブピクセル補正を有効化
  3) 選択中ID（0〜4）に一致するマーカーだけ採用
       中心 (cx,cy) = 四隅の平均
       範囲 (x,y,w,h) = 四隅の外接矩形
  4) ピクセル → PDFポイント へ変換（×72/DPI）
  5) ページ回転がある場合 page.derotation_matrix で mediabox 座標へ補正
```

- **廃止**：テキスト検索、スケール総当たり、回転総当たり、テンプレートのリサイズ再2値化、NMS、インク比率フィルタ、サンプルマーク指定、カスタムテンプレート。
- 検出結果の戻り値形式は現状踏襲：`{ページ番号: [(x, y, w, h), ...]}`（PDFポイント・mediabox座標）。これにより **`pdf_stamper.py` は無改修**。

## 6. 押印処理（変更なしの範囲と接続）

`pdf_stamper.py` は現行のまま利用：

1. 検出矩形 `(x,y,w,h)` を **白い四角で塗りつぶし**（マーカー領域＋余白2pt）。ArUco四隅由来の正確な範囲なので、印鑑サイズに依存せずマーカーが確実に消える。
2. 印鑑PNGを生成し、**中心 = 検出矩形の中心** に配置。
3. 回転ページは従来どおり印鑑を事前回転（PIL）させ、正立で表示。

## 10. エラー処理

| 状況 | 挙動 |
|------|------|
| 選択IDがそのページに無い | 押印なし（正常） |
| ID 0〜4 以外のArUco／その他の模様 | 無視（＝誤検出ゼロの根拠） |
| ページ画像化に失敗 | そのページを飛ばして継続（アプリは停止しない） |
| マーカーがページ端で見切れる | 検出された四隅から矩形を作成し、ページ範囲にクランプ |
| 文書全体で選択IDが0件 | 「0件検出」を表示し押印しない |

## 11. テスト方針

ArUcoを埋め込んだPDFを生成し、次を自動検証（pytest）：

- (a) **デジタル挿入**：ArUco PNGをページに挿入したPDF → 正しい座標で検出
- (b) **擬似スキャン**：マーカーを画像化（ノイズ・低DPI想定）したPDF → 検出
- (c) **回転ページ**：`/Rotate 90` のページ → mediabox座標へ正しく変換して検出
- (d) **誤検出ゼロ**：漢字・記号・丸・別IDのArUcoが大量にある無関係ページ → 選択IDの検出が**0件**
- (e) **中心精度**：検出中心が既知の配置中心とほぼ一致
- (f) マーカー書き出し：PNG/SVG/印刷PDFが生成され、生成PNGを再検出して往復一致

## 12. 後方互換・移行

- **旧マーク（㊎㊗㊦㊨㊀）で印を付けた既存PDFは検出されなくなる。** 新ArUcoマーカーへの貼り替えが必要。誤検出ゼロを優先するための割り切り（ユーザー合意済み）。
- 旧 `settings.json` の `selected_mark`（文字）はロード時にID 0へ補正され、アプリは正常起動する。

## 14. リスクと対策

| リスク | 対策 |
|--------|------|
| Word/Excelの画像圧縮でマーカーが劣化 | 高解像度PNGで書き出し＋SVG提供＋圧縮無効化手順を案内。ArUco 4×4は元来圧縮に強い |
| 印刷・貼付け時にマーカーが小さすぎ／歪み | `使い方.txt`に推奨10mm・縦横比固定・斜め禁止を明記。ArUcoは多少の歪みは許容 |
| マーカーを白塗りした箇所の罫線が消える | 従来同様、印鑑で隠れる前提。影響は受容 |
| 既存の旧マークPDFが未対応化 | 移行手順（貼り替え）を周知。セクション12に明記 |
| ごく低画質スキャンで未検出 | 検出DPIを250で実施。必要なら300へ調整可能（実装で定数化） |
